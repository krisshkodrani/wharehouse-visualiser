# ADR 0003: The LLM proposes placements; it never controls anything

Status: accepted.

`PlacementAdvisor` may suggest which eligible slot each incoming load should occupy, but it cannot originate a task, move a vehicle, or reserve capacity on its own authority. Before the model is called, `WarehouseStore.candidates()` computes the eligible slots and `AisleDirective.restrict()` narrows them to any aisle the operator named in free text; the model chooses only from that pre-filtered set and cannot see or select a slot outside it. Its response passes two independent checks before it can touch domain state: the OpenRouter call itself is constrained by a strict JSON schema, and `PlanningWorker.validate()` then re-derives, from first principles, that the plan covers exactly the requested loads once each and only uses slots from the allowed set, rejecting duplicates and omissions regardless of what the schema let through. `WarehouseStore.createPlannedJobs` re-checks slot capacity atomically at write time, so a race between candidate computation and commit cannot double-book a slot. Route planning is deterministic A* (`RoutePlanner`) and is never delegated to the model. With `AI_PROVIDER=mock`, the same validation path runs against a deterministic nearest-slot stand-in, so the safety layer is exercised on every run, not only when OpenRouter is configured. The cost is an extra validation pass and a candidate-filtering step the model cannot bypass; the benefit is that a hallucinated or malicious response can be rejected but never mutate inventory, dispatch a vehicle, or bypass an operator's stated constraint.
